# Pi Agent Harness 项目分析：功能架构、模块与本地快速启动

> 分析基于仓库当前代码（`main` 分支），结合源码路径与关键实现梳理，而非仅依赖 README 描述。

---

## 1. 项目概述

**Pi Agent Harness** 是一个 MIT 协议开源的**终端编码 Agent（Coding Agent）**框架，发布名称为 `@earendil-works/pi-*`，CLI 命令为 `pi`。它是一套"极简核心 + 高度可扩展"的自扩展编码 agent：

- 内置能力极简，默认只给模型 4 个工具：`read` / `write` / `edit` / `bash`；
- 不内置 sub-agent、plan mode 等重量级功能，而是通过 **Skills（技能）/ Extensions（TypeScript 扩展）/ Prompt Templates（提示词模板）/ Themes（主题）** 由用户自行装配，并可打包为 **Pi Packages** 通过 npm 或 git 分享；
- 支持 **4 种运行模式**：交互式 TUI、Print/JSON 非交互输出、RPC 进程集成、SDK 嵌入。

官方文档：<https://pi.dev>。仓库以 npm workspaces 组织为 monorepo。

## 2. 功能架构设计

### 2.1 分层架构总览

```text
┌─────────────────────────────────────────────────────────────┐
│ 应用层  packages/coding-agent (@earendil-works/pi-coding-agent) │
│  CLI（bin: pi）· 4 种模式 · 会话/配置/扩展/信任机制              │
├─────────────────────────────────────────────────────────────┤
│ 运行时层  packages/agent (@earendil-works/pi-agent-core)        │
│  Agent Loop · 工具执行 · 状态管理 · 压缩 · 事件流               │
├─────────────────────────────────────────────────────────────┤
│ 基础设施层                                                    │
│  pi-ai（统一 LLM API） · pi-tui（终端 UI）                     │
│  protocol/client/server（CBOR 远程会话） · telemetry · backends │
└─────────────────────────────────────────────────────────────┘
```

依赖方向：`coding-agent → agent-core → pi-ai / pi-tui`，各包均为独立 npm 包，可单独发布与复用。

### 2.2 核心执行流程（Agent Loop）

运行时核心位于 `packages/agent/src/agent.ts` 与 `packages/agent/src/agent-loop.ts`：

1. **消息模型统一**：整个循环以 `AgentMessage`（user / assistant / toolResult）贯穿，**只在调用 LLM 的边界**（`agent-loop.ts` 顶部注释明确）转换为供应商的 `Message[]`，见 `defaultConvertToLlm()`；
2. **循环调度**：`agentLoop()` / `runAgentLoopContinue()` 驱动"LLM 生成 → 工具调用 → 工具结果回填 → 下一轮"的循环，通过 `EventStream<AgentEvent, AgentMessage[]>` 对外发射事件（流式增量、工具开始/结束、轮次更新等）；
3. **可插拔流函数**：默认流式实现 `getDefaultStreamFn()`（`stream-fn.ts`），通过 `StreamFn` 抽象可替换为任意传输；
4. **上下文钩子**：`types.ts` 中定义了 `BeforeToolCall` / `AfterToolCall` / `PrepareNextTurn` / `ShouldStopAfterTurn` 等钩子类型，提供细粒度的行为干预点；
5. **用量统计**：内置 `EMPTY_USAGE` 与 token 成本核算结构，供 `usage-totals.ts`（coding-agent 侧）汇总。

### 2.3 模型与供应商架构（pi-ai）

`packages/ai/src/` 是全项目最大的横向能力，核心设计：

- **统一 `Provider` 抽象**：每个供应商以 `createProvider()` 声明式注册（`providers/deepseek.ts` 为典型样例）：

  ```ts
  createProvider({
    id: "deepseek",
    name: "DeepSeek",
    baseUrl: "https://api.deepseek.com",
    auth: { apiKey: envApiKeyAuth("DeepSeek API key", ["DEEPSEEK_API_KEY"]) },
    models: Object.values(DEEPSEEK_MODELS),
    api: openAICompletionsApi(),
  })
  ```

  由 `id / name / baseUrl / auth / models / api` 六要素构成，`api` 复用少数协议实现（如 `openai-completions`），实现"一套协议适配多家厂商"；
- **自动模型发现**：`models-store.ts` 定义 `ModelsStore` 接口（`read/write/delete`），基于远端 catalog 的 **ETag / Last-Modified** 做增量缓存，模型目录自动刷新（`pi update --models` 可强制刷新）；`models.generated.ts` / `image-models.generated.ts` 为构建期生成的模型快照，支持离线构建；
- **认证体系**：`auth/` 目录支持 API Key（`env-api-key`）、OAuth 订阅登录（`oauth.ts`、`bun-oauth.ts`，覆盖 Claude Pro/Max、ChatGPT Plus、GitHub Copilot）；
- **供应商规模**：`providers/` 目录下 60+ 供应商（Anthropic、OpenAI、Google、DeepSeek、Moonshot、Qwen、ZAI、MiniMax、Azure、Bedrock、Groq、NVIDIA、GitHub Copilot、OpenAI Codex、Cloudflare 等），另有 `faux.ts` 用于无 API 的测试场景。

### 2.4 内置工具集

`packages/coding-agent/src/core/tools/`（CLI 侧）与 `packages/agent/src/harness/tools/`（运行时侧）各维护一套工具，核心实现：

| 工具 | 文件 | 说明 |
|------|------|------|
| read | `read.ts` | 读取文件（含分页、图片等） |
| write | `write.ts` | 写文件 |
| edit | `edit.ts` / `edit-diff.ts` | 精确字符串替换与 diff 应用 |
| bash | `bash.ts` | shell 命令执行 |
| find / grep / ls | `find.ts` / `grep.ts` / `ls.ts` | 文件检索（CLI 侧） |
| image | `harness/tools/image.ts` | 图片处理（运行时侧） |

配套机制：`file-mutation-queue.ts`（文件写入串行队列，避免并发冲突）、`output-accumulator.ts`（工具输出累积）、`tool-definition-wrapper.ts`（工具定义包装）。

### 2.5 终端 UI 架构（pi-tui）

`packages/tui/src/` 是自研终端 UI 库，两个渲染器：

- `tui-main-screen.ts`：主屏模式，交给终端滚动缓冲（scrollback）渲染，适合流水式输出；
- `tui-alt-screen.ts`：备用屏模式，应用接管全屏渲染，支持**差分渲染**（按行 diff 只写变化行）以提升效率；
- **布局系统**：`components/` 下 `v-stack.ts` / `h-stack.ts` / `scroll-view.ts` / `stack.ts` 构成 VStack/HStack/ScrollView 布局原语；`layout.ts` + `layout-node.ts` 是内部布局引擎（约束布局、裁剪、命中测试、滚动链），详见 `tui-plan.md` 的设计交接文档；
- 丰富组件：`editor.ts`（多行编辑器）、`markdown.ts`（Markdown 渲染）、`image.ts`（Kitty 协议图片）、`select-list.ts` / `settings-list.ts`、`autocomplete.ts`、`input.ts` 等；
- 交互能力：`keybindings.ts` / `keys.ts`（可配置键位）、`alt-screen-search.ts`（搜索）、`undo-stack.ts`、`kill-ring.ts`、`word-navigation.ts`、`terminal-image.ts`、IME 支持。

### 2.6 会话与状态管理

- **会话后端抽象**：`packages/session-backends/sqlite-node` 提供 SQLite 会话持久化（`@earendil-works/pi-session-backend-sqlite-node`），`packages/agent/src/harness/session` 定义会话接口；
- **Compaction（上下文压缩）**：`packages/agent/src/harness/compaction/` 与 `packages/coding-agent/src/core/compaction/` 实现长对话自动摘要压缩，控制上下文窗口占用；
- **Session 分支**：coding-agent 支持会话分支（branching），见 `core/session-manager.ts`。

### 2.7 远程会话（实验性）

- `packages/protocol`：传输无关的 **CBOR** 协议定义（基于 TypeBox schema）；
- `packages/client`：`@earendil-works/pi-client`，framed CBOR 字节流上的远程会话客户端；
- `packages/server`：实验性 server 包。
- 三者支撑"远程跑 agent、本地看 UI"的架构方向。

### 2.8 运行模式与扩展机制

`packages/coding-agent/src/modes/` 导出四种模式：

| 模式 | 入口 | 用途 |
|------|------|------|
| 交互式 TUI | `interactive/interactive-mode.ts` | 终端对话、编辑器、消息队列 |
| Print / JSON | `print-mode.ts` | 非交互一次性输出（`-p`），JSON 事件流 |
| RPC | `rpc/rpc-mode.ts`、`rpc-client.ts` | 进程间集成（命令/事件/扩展 UI） |
| SDK | `packages/coding-agent/src/sdk.ts`、`main.ts` | 嵌入自有应用 |

扩展机制（`core/extensions/`、`extensions/`、`harness/skills.ts`、`core/slash-commands.ts`、`core/settings-manager.ts`）：Skills（技能目录）、Extensions（TypeScript 钩子与自定义工具）、Prompt Templates、Themes、Slash Commands，全部可在运行时加载，不要求 fork 仓库。

### 2.9 其他横切机制

- **遥测**：`packages/telemetry` 定义厂商无关的遥测契约与类型化 schema（`pi-telemetry`），`agent/src/harness/telemetry.ts` 接入；
- **安全/信任**：`core/trust-manager.ts`、`cli/project-trust.ts`（项目信任提示）、`core/project-trust.ts`；
- **认证管理**：`core/auth-storage.ts`、`core/runtime-credentials.ts`、`cli/auth-command.ts`（`/login`）、`cli/auth-check.ts`；
- **CI/质量**：根目录 `npm run check`（biome lint + 类型检查 + 依赖钉死校验 + shrinkwrap 校验）；`test.sh` 统一测试入口；供应链加固（`--ignore-scripts` 安装、lockfile 为唯一事实源、shrinkwrap 白名单）。

## 4. 项目特点

1. **极简核心、生态化扩展**：默认仅 4 个工具；Skills / Extensions / Templates / Themes / Pi Packages 五类扩展机制，避免 fork；
2. **厂商中立**：60+ LLM 供应商统一抽象，`api` 协议复用 + `auth` 策略化，模型目录自动发现（ETag 增量缓存）；
3. **四种运行模式**：交互 TUI、Print/JSON、RPC、SDK，一套核心多形态对外；
4. **自研终端 UI**：差分渲染 + VStack/HStack/ScrollView 约束布局，支持 Markdown、Kitty 图片、IME、鼠标、可配置键位；
5. **事件流驱动**：Agent Loop 全程以 `EventStream<AgentEvent>` 对外广播，UI/RPC/JSON 输出都是同一事件流的消费端；
6. **会话工程完备**：SQLite 持久化、compaction 压缩、session 分支；
7. **供应链安全**：依赖精确钉死、`--ignore-scripts` 安装、lockfile 唯一事实源、发布 shrinkwrap 白名单、依赖变更视为代码审查；
8. **可嵌入/可远程**：SDK 嵌入 + CBOR 远程会话协议（实验方向）。

## 5. 本地快速启动

### 5.1 环境要求

- **Node.js >= 22.19.0**（本项目 `package.json` engines 字段）
- npm（workspaces 自动识别）
- 一个 LLM 供应商的 API Key（或 Claude Pro/Max、ChatGPT Plus、GitHub Copilot 订阅）

### 5.2 从源码启动（推荐用于开发）

```bash
# 1. 安装依赖（必须加 --ignore-scripts，禁用生命周期脚本，仓库强制要求）
npm install --ignore-scripts

# 2. 构建。仓库已含 packages/ai/src/models.generated.ts 模型快照，
#    用离线模式即可，无需联网刷新模型目录
npm run build:offline

# 3. 配置 API Key（任选其一）
export ANTHROPIC_API_KEY=sk-ant-...
# 或 export OPENAI_API_KEY=sk-... / DEEPSEEK_API_KEY=... 等

# 4. 从源码启动交互式界面（可从任意目录运行）
./pi-test.sh
```

说明：

- 已有订阅（Claude Pro/Max、ChatGPT Plus、GitHub Copilot）可先 `pi` 进入后执行 `/login` 选择供应商登录，无需 API Key；
- 切换模型：交互界面内 `/model` 或 `Ctrl+L`；
- `build`（联网）与 `build:offline`（离线）区别：前者刷新各供应商实时模型目录，后者使用仓库内置快照。本仓库已带 `models.generated.ts`，**默认用离线构建即可**；
- 命令行测试可加 `-p "你的问题"` 进入 print 模式，或 `--no-env` 清空 API 环境变量（见 `pi-test.sh`）。

### 5.3 直接安装发布版（快速体验）

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
pi
```

或官方安装脚本：`curl -fsSL https://pi.dev/install.sh | sh`

### 5.4 项目内配置文件方式（本项目已配置，推荐）

pi 原生支持**项目级设置**：`<项目根>/.pi/settings.json`，通过 `deepMergeSettings(全局, 项目)` 合并且**项目优先**（源码：`packages/coding-agent/src/core/settings-manager.ts` 的 `projectSettingsPath`）。本项目已在根目录建好一套本地配置文件：

| 文件 | 作用 | 说明 |
|------|------|------|
| `.pi/settings.json` | 模型配置 | 固定 `defaultProvider: "deepseek"`、`defaultModel: "deepseek-v4-pro"`，可选 `deepseek-v4-flash` |
| `.env` | API Key 配置 | 已被 `.gitignore` 忽略，不会提交；填入 `DEEPSEEK_API_KEY=sk-...` |
| `run-pi.sh` | 一键启动脚本 | 自动 `source .env` 注入 key，并屏蔽 shell 中残留的 Anthropic 中转变量，然后启动 pi |

```bash
# 1. 编辑 .env，填入真实 key
DEEPSEEK_API_KEY=sk-你的key

# 2. 启动（之后统一用这个命令，不要直接 ./pi-test.sh）
./run-pi.sh
```

说明：pi 本身**不会自动加载 `.env`**（无 dotenv 机制），所以用 `run-pi.sh` 代为注入环境变量；settings 的 `Settings` 接口（`settings-manager.ts`）不含 API Key 字段，key 必须走环境变量或 `auth.json`，这也是项目内 `.env` 方案存在的原因。

### 5.5 常用开发命令

| 命令 | 说明 |
|------|------|
| `npm run build` | 联网刷新模型数据后构建全部包 |
| `npm run build:offline` | 用现有模型快照离线构建 |
| `npm run check` | lint + 格式化 + 类型检查 + 依赖/锁文件校验 |
| `./test.sh` | 运行全部非 e2e 测试（无 API Key 时跳过 LLM 依赖测试） |

## 6. 模型与 Key 配置

### 6.1 配置位置总览

| 配置项 | 位置 | 来源代码 |
|--------|------|----------|
| 全局配置目录 | `~/.pi/agent/`（可用 `PI_CODING_AGENT_DIR` 覆盖） | `config.ts` `getAgentDir()` |
| API Key 环境变量 | `ANTHROPIC_API_KEY`、`OPENAI_API_KEY`、`DEEPSEEK_API_KEY` 等 | `ai/src/env-api-keys.ts` |
| OAuth 订阅凭证 | `~/.pi/agent/auth.json`（`/login` 写入） | `core/auth-storage.ts` |
| 全局设置（默认模型等） | `~/.pi/agent/settings.json` | `config.ts` `getSettingsPath()` |
| 项目级设置（**优先于全局**） | `<项目根>/.pi/settings.json` | `settings-manager.ts` |
| 自定义/补充模型 | `~/.pi/agent/models.json` | `config.ts` `getModelsPath()` |
| 模型目录缓存 | `~/.pi/agent/models-store.json` | `ai/src/models-store.ts` |

### 6.2 设置默认模型

```jsonc
// ~/.pi/agent/settings.json 或 <项目根>/.pi/settings.json
{
  "defaultProvider": "deepseek",
  "defaultModel": "deepseek-v4-pro",
  "enabledModels": ["deepseek/deepseek-v4-pro", "deepseek/deepseek-v4-flash"]
}
```

项目级 settings 与全局合并时**项目优先**；会话内也可用 `/model`（或 `Ctrl+L`）临时切换。

### 6.3 常见问题排查

- **默认模型选择逻辑**：`model-resolver.ts` 中 `defaultModelPerProvider` 按内置顺序遍历（`anthropic` 排在 `deepseek` 前），只要检测到对应供应商的认证（环境变量或 auth.json），就选中该供应商默认模型。**残留的 `ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN` 会令 pi 误走 Anthropic 通道**，即使已配置 DeepSeek key；
- **403 `Request not allowed`**：若经第三方中转调用 Anthropic，多为中转/上游拒绝（如中转不支持 Anthropic 协议、官方算力限制、地域封锁）。优先改用国内可直连供应商（DeepSeek、Moonshot、Qwen、ZAI、MiniMax），或联系中转管理员；
- **401 认证失败**：检查 key 是否为空/格式错误，DeepSeek 要求 `Bearer sk-...` 格式。
